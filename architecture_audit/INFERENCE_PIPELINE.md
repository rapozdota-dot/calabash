# Calabash inference pipeline

The deployed model is one offline FP32 TFLite graph. Camera acquisition, file decoding, letterboxing, non-maximum suppression, mask reconstruction, temporal tracking and Flutter rendering are application operations. The [neural network report](HYBRID_ARCHITECTURE.md) traces the operators inside the artifact.

## Shared model execution and output decoding

1. **Letterbox.** Compute `gain=min(640/W,640/H)`. Resize to rounded dimensions using the Dart image library's linear interpolation. Left and top offsets use `round(pad/2−0.1)`, with the remainder placed on the right or bottom. Fill the canvas with RGB 114. Pack planar RGB float32 values divided by 255 for this export. The decoder validates input/output dtypes and resolves supported layout variants from shape. No ImageNet mean/std normalization is applied by the app. [ModelService:515–573](../lib/services/model_service.dart#L515-L573), [tensor packing:29–87](../lib/services/image_tensor_layout.dart#L29-L87), [signature:1030–1110](../lib/services/model_service.dart#L1030-L1110)
2. **Execute.** Use `tflite_flutter` `Interpreter.fromAsset` or `fromBuffer`. Write the packed tensor, call `invoke()`, then bulk copy both outputs from native tensor buffers. The audited artifact has FP32 input `[1,3,640,640]`, detections `[1,39,8400]` and channel-first prototypes `[1,32,160,160]`. The deployed artifact uses neither a server call nor a second classifier for inference. [ModelService:227–273](../lib/services/model_service.dart#L227-L273), [ModelService:589–616](../lib/services/model_service.dart#L589-L616)
3. **Score and decode.** Read `channel * 8400 + candidate`. Take the highest of channels 4–6 and require a finite score strictly greater than 0.45 and at most 1. Reject invalid boxes and nonfinite coefficient vectors. Multiply normalized `cx,cy,w,h` by 640, form corners, clip to model space, subtract padding and divide by gain, then clamp to the oriented source image. [Parser:682–820](../lib/services/model_service.dart#L682-L820), [geometry:823–872](../lib/services/model_service.dart#L823-L872), [indexing:1218–1231](../lib/services/model_service.dart#L1218-L1231)
4. **Suppress duplicates.** Sort candidates by descending score. Compare boxes clipped to the 640×640 model canvas. Suppress IoU strictly greater than 0.60 for the same class and 0.85 across classes. Cap kept candidates before mask work at 300 for photo and 20 for live. [ModelService:449–459](../lib/services/model_service.dart#L449-L459), [postprocessor:14–71](../lib/services/segmentation_postprocessor.dart#L14-L71), [constants:9–22](../lib/utils/constants.dart#L9-L22), [live worker:633–641](../lib/services/live_inference_worker.dart#L633-L641)
5. **Reconstruct masks.** Interpret channels 7–38 as a 32-value coefficient vector. For each survivor, convert its model box to a clipped 160×160 prototype crop with floor on left/top and ceil on right/bottom. Within that crop, calculate `L(y,x)=Σ c[k]×P[k,y,x]`. Require finite crop logits and at least `max(4, ceil(0.10 × crop area))` pixels above zero. Map source-box sample centers through the letterbox into the prototype grid and sample the containing cell. Build a compact binary grid with long side 72 and short side clamped to 18–72. Apply a 3×3 vote requiring four active neighbors and discard an empty final mask. [Postprocessor:74–175](../lib/services/segmentation_postprocessor.dart#L74-L175), [ModelService:875–1005](../lib/services/model_service.dart#L875-L1005)
6. **Publish.** Normalize bounds relative to source width and height. Map class indices 0/1/2 to Immature/Mature/Overmature. The photo result fits the image and overlays the per-instance masks in the same rectangle, with class-colored fill/edge and labels. Result state derives counts and guidance from kept detections, and displays selected-class confidence rounded to a whole percentage. The live provider checks freshness and session generation, associates detections across frames and stabilizes labels before fitting the mask and label overlay to the preview. Tentative and stabilized live labels can differ from a single raw frame. [ModelService:1391–1420](../lib/services/model_service.dart#L1391-L1420), [photo image:100–163](../lib/widgets/detection_image.dart#L100-L163), [mask painter:295–330](../lib/widgets/detection_box.dart#L295-L330), [confidence:63–75](../lib/widgets/result_card.dart#L63-L75), [live publish:902–947](../lib/providers/live_camera_provider.dart#L902-L947), [live overlay:409–485](../lib/screens/live_camera_screen.dart#L409-L485)

## Python diagnostic and parity

`tool/diagnose_model.py` runs the same TFLite export with two LiteRT threads and uses Pillow EXIF transpose, RGB conversion, centered RGB-114 padding, bilinear resize, NumPy float32 /255, and shape-dependent channel ordering. Pillow and Dart image sampling, Python and Dart rounding at ties, photo picker resizing/compression, and live YUV/BGRA conversion can produce different inputs. The tool's optional crop/rotation/stretch probes are diagnostic only. It reports raw `xywh`, top-five candidate class scores and coefficient ranges, counts above 0.45 and 0.25, and can dump the tensors. It performs no Flutter NMS, mask support/smoothing, original-coordinate detection rendering, or live temporal tracking. The repository has no PyTorch inference/validation or training preprocessing code for an original-framework parity check. [Preprocessing:12–25](../tool/diagnose_model.py#L12-L25), [diagnostic:28–54](../tool/diagnose_model.py#L28-L54), [input probes:57–91](../tool/diagnose_model.py#L57-L91).

## Processing time

| Measurement | Boundary |
| --- | --- |
| `interpreter_invoke_ms` | Elapsed `Interpreter.invoke()` only. Native runtime/delegate overhead is included. |
| `yolo_inference_ms` | Tensor input assignment + invoke + bulk output copies. This covers the whole hybrid graph, including the backbone and Proto branch. |
| `model_preprocess_ms` | Model letterbox resize and RGB input fill. The live `preprocess_ms` aggregate adds pixel conversion and orientation. |
| `postprocess_ms` | Candidate parsing, NMS, prototype handling, instance masks and detection conversion. |
| Gallery and Capture complete processing | Starts once a selected gallery file returns or the captured file enters `scanFile`. Includes the worker, file read/decode, initialization, model/postprocessing, return and prepared result. Picker interaction, shutter/file creation and final rendering are outside the boundary. |
| Live complete processing | Starts at Dart frame callback receipt for the recorded frame and includes queue wait, transfer, conversion, model inference, postprocessing and result preparation. `processing_ms` subtracts queued wait. Sensor exposure, camera preview rate, and final rendering are outside this measurement. |

Recording is opt-in via `CALABASH_PERF`. The timing windows and eligible rows must match for study comparisons.
